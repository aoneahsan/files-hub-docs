Social accounts

A record of which email holds which social account, and which project each account belongs to. It works in both directions: open a project to see its accounts and who holds them, or open an email to see every account it holds, project by project.

It exists because LinkedIn lets one person make only a few company pages and then makes them wait about a week. Pages get made through several people's emails, and this keeps track of whose.

Available since backend 2026.11.19.1. In the dashboard: Nova → Social Media, and the Social Media tab on every project.

The three pieces​

PieceWhat it is
Social identityAn email that holds accounts: yours or a team member's, with who holds it
Social accountOne account on one platform, held through one identity: a LinkedIn profile, a LinkedIn company page, an X account, a YouTube channel
Project linkAn account belongs to any number of projects, each with a role: official, promotion or personal_brand

Nothing here is a secret. A login is a link to a dashboard Password Manager entry, returned as {public_id, title}. The password itself never appears in any response.

An account's status is active, pending, restricted or closed. A closed account no longer counts as "having" one, so its project shows up again in projects without social media.

Access​

CallToken needs
Every readcan_read_vault (or can_reveal_vault / can_write_vault)
Every writecan_write_vault
GET /social-platformsAny valid token

Projects are seen through the token. A project the token can't reach is left out of every projects list. Naming one in a write returns 404, the same as a project that doesn't exist.

Platforms​

GET /api/public/v1/social-platforms

Returns the platforms (20 today: LinkedIn, X, Facebook, Instagram, Threads, TikTok, YouTube and more), the kinds each one offers, and page_cooldown_days, which is 7 for LinkedIn. Read it rather than hard-coding the list. An X account is never a page, so asking for a kind the platform doesn't offer returns 422 INVALID_KIND.

Record a new page the moment you make it​

POST /api/public/v1/social-identities
{"email": "pages.desk1@example.com", "held_by": "Team member A"}
POST /api/public/v1/social-identities/pages.desk1@example.com/accounts
{
  "platform": "linkedin",
  "kind": "page",
  "name": "PregnancyPal",
  "url": "https://www.linkedin.com/company/pregnancypal",
  "created_on_platform_at": "2026-11-19",
  "projects": [{"project": "pregnancypal", "role": "official"}]
}

An identity is addressed by its id or its email; an account only by its id. A second identity with the same email returns 409 SOCIAL_IDENTITY_ALREADY_EXISTS, so PATCH that one instead.

created_on_platform_at on a LinkedIn page sets the identity's next_linkedin_page_on. That's now, or the date the 7-day wait ends. Check it before choosing whose LinkedIn makes the next page.

Read it either way​

FromCall
An emailGET /social-identities/{identity}: its accounts, each with its projects
A projectGET /projects/{project}/social-accounts: its accounts, each with the email and holder, plus not_on (platforms with no live account)
SearchGET /social-identities?q=tilawah: matches the email, holder, account names, handles, links and project names

Both lists, GET /social-identities and GET /social-accounts, are paginated (per_page, page; meta has the totals). They filter by platform and project, and accounts also by kind, status and identity.

Change links​

CallEffect
PUT /social-accounts/{account}/projects {"projects": [{"project": "tilawah", "role": "promotion"}]}This account belongs to exactly these projects. [] detaches them. Links to projects your token can't see are left alone
PUT /projects/{project}/social-accounts {"accounts": [{"account": "<id>", "role": "official"}]}This project has exactly these accounts
PATCH /social-accounts/{account}Change any field. projects, when sent, replaces the set
DELETE /social-accounts/{account}Removes the record and its links. To keep the history, set "status": "closed" instead

Projects without social media​

GET /api/public/v1/social-accounts/missing?lifecycle=production&missing_on=linkedin,facebook

The same lists as the two Nova lenses: Production projects without social media and All projects without social media (lifecycle=all). With no missing_on, it lists projects with no live account at all. With platforms, it lists projects with no live account on at least one of them. Each row has has_accounts_on with counts per platform.

The full request and response shapes are in openapi.json under the Management API tag.
