Other apps

If you belong to a FilesHub project, you can let your own scripts, an AI assistant or another server work with that project's files, usage and email log. You set this up yourself on FilesHub, under Account → Other apps, and you can see exactly what each connection reaches.

There are three ways in. FilesHub calls them doors:

DoorForPage
Access keysA script or server of yours, sending fh_usr_ keysAccess keys · The API
AssistantsClaude, ChatGPT, Claude Code, CursorAssistants
WebhooksYour server, told when something happensWebhooks
An admin switches each door on

Each door has its own switch in FilesHub's admin panel, and all three start off. While a door is off, everything behind it answers 404, nothing can be made on its tab, and Other apps says so on that tab. Two-step sign-in is not behind a switch.

Who this is for​

A person here is someone whose request for dashboard access was approved. The approval makes them a member of named projects, with one of two roles in each:

RoleCan seeCan ask to delete a file
ViewerYesNo — a delete asked for in this project is refused
OperatorYesYes — and the delete still waits for their yes on FilesHub

People sign in with Google only. After approval, signing in takes you straight to Other apps.

Admins are not people in this sense. Their keys and assistants are the Management API and the vault's own MCP server, which stay exactly as they are.

What each door reaches​

Only your own projects, and only what you could already see or do on FilesHub yourself. A key or an assistant reaches no more than it was given when you made it.

FilesName, size, type, uploaded, public or privateSee. Delete waits for your yesSee. Delete waits for your yesUploaded, deleted: id, name, size, project. Never the file

Uploading and renaming come to keys once your project's Files page on FilesHub has those buttons. Until then a key can see files and ask to delete one.

Why no message bodies: a sent email holds other people's details and often a one-time link, such as a password reset. The log says it went; the message stays with the person it was for.

Never reachable, through any door​

Not with any key, any assistant or any webhook, whatever it was given:

  • vault values, vault files and .env blocks of any project;
  • revealing any credential, API key or Supabase secret;
  • any fh_live_ project key or fh_pat_ management token;
  • Password Manager entries;
  • AI account keys and AI credit;
  • Developer Accounts: npm, store and hosting tokens;
  • Payment Accounts and payouts;
  • Supabase account tokens and project secrets;
  • database backups;
  • email message bodies, attachments and email-marketing lists;
  • other people's projects, files and logs;
  • Nova, plans, payments and two-step settings.

Anything outside your projects answers 404, never 403, so a key cannot learn what exists.

An access key is not a management token​

FilesHub already has management tokens (fh_pat_), which the owner makes in Nova to run projects, keys and vaults, and project API keys (fh_live_) for the data API. Both stay exactly as they are. An access key is a separate, narrower thing for one person's own projects:

Access keyManagement token
Starts withfh_usr_fh_pat_
Made byYou, on Other appsThe owner, in Nova
ReachesYour projects' files, usage, email logProjects, API keys, origins, vaults, backups, by scope
Shows a secretNeverWith its reveal scopes
Expires30, 90 or 365 days; "never" for see-only keysAs the owner set it
Seen againWithin 10 minutes of a sign-in, with your codeUnchanged
DocsAccess keysManagement API

Neither works in the other's place. The person API answers an fh_pat_ or fh_live_ value with 401 wrong_credential, and the management and vault routes accept only their own prefixes, so an fh_usr_ key gets nowhere there.

Limits​

Four limits apply to each person: access keys, API requests a day, webhook endpoints and connected assistants. They come from the service plans in force on your projects, and the highest one counts. When none of your projects has a plan in force, the base limits an admin sets for people apply. The Plan use tab on Other apps shows what you have used and what you are allowed.

Lowering a limit never deletes anything: if you are over it, you keep what you have and cannot add more. API requests start again at midnight GMT+5.

Emails FilesHub sends you​

FilesHub emails you when a key is made, seven days before a key ends, when an assistant connects, when something asks to delete a file, when a webhook endpoint is turned off for failing, and when anything about your two-step sign-in changes. A key or secret is never in an email.
